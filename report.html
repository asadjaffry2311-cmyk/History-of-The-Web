Implementation Report

How This Website Was Built

This page documents the planning, design, and technical decisions behind this website — from the choice to build without a template to the CSS properties used to create a consistent visual identity. It serves as our technical exam report.

Project Type Static Website
Technologies HTML · CSS · JavaScript
Hosting GitHub Pages
Pages 4 (Home · Timeline · How It Works · Report)
Live URL asadjaffry2311-cmyk.github.io
01
Template Selection

Why We Built Without a Template

We deliberately chose not to use a pre-made template for this website. Instead, we built the entire site from scratch using only HTML and CSS, hosted via GitHub Pages. This decision was guided by three reasons:

  • Academic understanding. Building without a template required us to understand every element we used — every tag, every CSS property, every layout decision. We could not rely on pre-written code we did not fully understand.
  • Full control. A custom build gave us direct control over the page structure, navigation, colour palette, typography, and responsive behaviour — all of which needed to reflect the educational purpose of the site.
  • Alignment with course goals. The course asked us to apply theoretical knowledge of web technologies to a practical environment. Building from scratch is a more direct demonstration of that knowledge than modifying an existing template.

The site was built as a static website — meaning all pages are pre-built HTML and CSS files, served directly by GitHub Pages without any server-side processing. This is both appropriate for the project's scope and a direct demonstration of the concepts discussed on the How It Works page.

02
Information Architecture

How We Organised the Site

The site is organised into four pages, arranged in a deliberate progression — from broad context to technical explanation to critical reflection. Each page builds on the previous one:

01
Home

Introduces the topic, its historical and semiotic relevance, and provides a glossary of key terms. Acts as the entry point and orientation for all other pages.

 02
Timeline

Traces the chronological development of the Web from ARPANET (1969) to the social and mobile Web of today, with sourced facts, images, a comparison table, and a glossary.

 03
How It Works

Explains the technical process behind opening a website: DNS, TCP/IP, HTTP requests and responses, HTML rendering, the DOM, and the difference between static and dynamic sites.

 04
Report (this page)

Documents the design decisions, HTML structure, CSS choices, and challenges encountered during development. Serves as the technical exam report.

Navigation is handled by a sticky top bar present on all four pages. The active page is always highlighted in blue so the user always knows where they are. Each page also links to the others through contextual inline links within the text, creating a network of connections — a structure that itself mirrors the hyperlink logic of the Web.

03
Stylistic Choices

Design Decisions and Their Rationale

Every visual decision was made deliberately to support the educational purpose of the site. We were inspired by the design language of CERN's website — authoritative, clean, and content-first.

Colour Palette

The site uses a dark navy and white palette for the navigation, headers, and footer — conveying authority and seriousness. The body uses a warm off-white background (#f5f4f0) rather than pure white, which reduces eye strain on long reads. The accent colour is a mid-blue (#0057a8), used consistently for links, active states, card borders, and interactive elements. All colours are defined as CSS custom properties (variables) in the :root selector, making them easy to change consistently across the entire site.

Navy #0e1a2b Header · Footer · Nav
Blue #0057a8 Links · Accents · Active
Off-white #f5f4f0 Page background
White #ffffff Cards · Sections
Gold #c9942a Accent highlights

Typography

The site uses two typefaces loaded from Google Fonts:

  • Merriweather (serif) — used for all headings (h1, h2, h3). A serif face conveys academic seriousness and readability, appropriate for an educational resource.
  • Inter (sans-serif) — used for all body text, navigation, and captions. A clean, highly legible typeface designed specifically for screen reading.

Font sizes use the CSS clamp() function for fluid scaling — headings grow and shrink smoothly between screen sizes without fixed breakpoints.

Layout

Page content is constrained to a maximum width of 1060px and centred with margin: 0 auto, keeping lines of text readable even on wide screens. The site uses CSS Grid for multi-column layouts (cards, comparison tables, two-column sections) and CSS Flexbox for one-dimensional arrangements (navigation, stat strips, footer). padding, margin, and gap properties control all spacing. border-radius creates the rounded card corners. box-shadow lifts cards off the background to create visual depth.

04
HTML & CSS Logic

How the Code Is Structured

HTML Structure

Every page uses the same semantic HTML skeleton, ensuring consistency across the site. Semantic tags are used throughout — not for visual reasons, but because they communicate meaning about the content they contain:

HTML Tag What it contains Why it was used
<nav> Navigation links Signals navigability to browsers and screen readers
<main> Primary page content Identifies the central content, skipping nav and footer
<section> Thematic content blocks Groups related content with a clear heading
<article> Individual cards Marks self-contained content items
<figure> Images with captions Associates an image with its description accessibly
<footer> Authors and project info Marks supplementary page metadata
<aside> Sidebar quote and image Marks content tangentially related to the main text

CSS Architecture

All styling is contained in a single external file, styles.css, linked to all four pages via the <link rel="stylesheet"> tag. This means any change to the stylesheet is instantly reflected across the entire site — a direct application of the separation of structure (HTML) and presentation (CSS).

The CSS file is organised into sections using comments, moving from global rules (CSS variables, reset, typography) to shared components (navbar, buttons, cards, footer) and then to page-specific additions. Each page's unique components use a distinctive class prefix to avoid conflicts: .vtl- for the timeline, .ww- for How It Works, and .rp- for this report page.

CSS Custom Properties

All colours, fonts, spacing values, and shadows are defined as CSS custom properties in the :root block:

:root { --c-navy: #0e1a2b; --c-blue: #0057a8; --c-bg: #f5f4f0; --c-surface: #ffffff; --font-display: 'Merriweather', Georgia, serif; --font-body: 'Inter', Arial, sans-serif; --radius-lg: 12px; --shadow-md: 0 6px 24px rgba(0,0,0,0.10); }

This system means the entire visual identity of the site can be changed by editing just a handful of lines at the top of the CSS file.

Accessibility

All non-text content has descriptive alt attributes. All navigation elements have aria-label attributes. The active page in the navbar uses aria-current="page". Images use loading="lazy" for performance. Links open in new tabs with target="_blank" rel="noopener noreferrer" for security.

05
Interactive Features

What Makes the Site Interactive

Beyond static HTML and CSS, the site uses a small amount of JavaScript and advanced CSS to create interactive and dynamic behaviour:

✨

Scroll Reveal Animation

Sections fade in and slide up as the user scrolls down the page. This uses the browser's IntersectionObserver API — a JavaScript tool that fires when an element enters the viewport. The animation itself is pure CSS transitions on opacity and transform.

💬

Hover Tooltips

Key technical terms throughout the site show a popup definition when hovered over. These use pure CSS — the ::after pseudo-element combined with content: attr(data-tip) reads the tooltip text directly from the HTML attribute. No JavaScript required.

🖱️

Hover Effects on Cards

Cards across the site lift and shift slightly on hover using transform: translateY(-3px) and an increased box-shadow, both animated with CSS transition. On the Timeline page, cards slide right with transform: translateX(6px).

📌

Sticky Navigation

The navigation bar uses position: sticky; top: 0 to remain visible as the user scrolls. The active page is highlighted with a blue background using the nav-active class, which sets background-color and color.

📅

Visual Timeline

The Timeline page uses a vertical line drawn with a CSS ::before pseudo-element on the .vtl-track container. Each era card is positioned with flexbox and uses border-left to connect visually to the line. The dot markers scale on hover using transform: scale(1.35).

📱

Responsive Design

CSS @media queries adjust the layout for screens narrower than 820px and 600px. Multi-column grids collapse to a single column. The navbar stacks vertically. Font sizes use clamp() to scale fluidly without fixed breakpoints.

06
Challenges

Technical Challenges Encountered

⚙️

Understanding CSS from Scratch

Since we did not use a template, every CSS property had to be written and understood from first principles. Concepts like the CSS box model, specificity, and the difference between margin and padding required careful study before we could apply them correctly. We referenced MDN Web Docs extensively throughout the process.

🖼️

Image Hosting and External Links

We encountered difficulty embedding images from external sources such as CERN and Wikimedia Commons, as many servers block hotlinking (direct embedding of images hosted elsewhere). The solution was to upload our images directly to the GitHub repository so they are served from the same domain as the site, ensuring they always load correctly.

📐

Sidebar Layout and Sticky Positioning

On the Home page, the quote box and Tim Berners-Lee image sit in a sidebar next to the main text. Getting the sticky positioning to work correctly — so the image stays fixed while the quote scrolls over it — required careful use of position: sticky, z-index layering, and align-self: stretch on the grid container. Duplicate CSS rules accumulated over iterations caused conflicts that had to be systematically identified and resolved.

📱

Responsive Design

Making the site work well on smaller screens required writing CSS @media queries that collapsed multi-column grids to single columns, stacked the navbar vertically, and adjusted padding and font sizes. The main challenge was ensuring that interactive elements (like the vertical timeline and the sticky sidebar) degraded gracefully on mobile without breaking the layout.

🎨

Maintaining CSS Consistency Across Four Pages

As the site grew to four pages with increasingly complex components, maintaining a single shared styles.css file without rules from one page affecting another required discipline. We solved this by prefixing every page-specific CSS class with a unique identifier (.vtl-, .ww-, .rp-), ensuring complete isolation between page-specific styles.

07
Conclusion

What We Learned

Building this website from scratch taught us something that reading about web technologies alone could not: that every technical decision is also a communicative decision. Choosing a tag, a colour, a font, or a layout is not a neutral act — it encodes assumptions about who will read the page, what counts as important, and how knowledge should flow.

HTML structures knowledge: a <h1> signals primacy, a <nav> signals navigability, a <section> groups meaning into digestible units. These are not arbitrary conventions — they are a sign system, and writing them requires thinking like a semiotician as much as a programmer. CSS adds a second layer: colour encodes hierarchy (dark navy for authority, blue for interactivity), spacing creates rhythm, and typography sets tone. The visual design of a page is itself a text — one that communicates before a single word is read.

Most importantly, this project made the Web concrete. Concepts that had existed for us only as definitions — DNS, HTTP, hyperlinks, TCP/IP — became things we used, debugged, and understood through practice. As Tim Berners-Lee designed the Web to be a space of human communication, we found that building even a small part of it is an act of communication in itself — one that requires both technical precision and semiotic awareness.
