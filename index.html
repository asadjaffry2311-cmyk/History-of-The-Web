Three Lenses on the Web

This site approaches the Web from three angles: its historical development, its technical architecture, and its cultural significance as a system of signs.

01

Historical Development

The Web grew out of decades of research into networked computing, beginning with ARPANET in the 1960s. According to CERN, it was originally designed so scientists worldwide could share information automatically — it only became a public tool after 1991.

Technical Structure

Behind every webpage is a conversation between a client and a server, governed by protocols. When you type a URL, DNS translates it into an IP address, TCP/IP routes the request, and HTTP defines how the server responds — all in milliseconds.

Semiotic Relevance

Semiotics — the study of signs and meaning — applies directly to the Web. Links structure navigation as argument. Layouts encode hierarchy. Interfaces make assumptions about users. As Berners-Lee wrote, the Web was designed as a medium of human communication.

Context

Why This Topic Matters

The history of the Web is not simply a history of technology. It is a history of how human communication was reorganised. Before the Web, documents lived in libraries, archives, and filing cabinets — separate, static, and difficult to connect. After 1991, any document could link to any other document, anywhere on the planet, instantly. That single structural change — the hyperlink — rewired how knowledge is produced, stored, and shared.

At the same time, this transformation did not happen automatically. It required decisions: about protocols, about open standards, about who could publish and who could access. Tim Berners-Lee famously chose not to patent the Web, making it a public good. As CERN records, in 1993 the source code was released on a royalty-free basis — a decision that shaped everything that followed. Studying the Web means asking not just how it works, but why it was built the way it was — and what values those choices encoded.

For students of semiotics, the Web is a particularly rich object of study. It is simultaneously an infrastructure and a text, a medium and a message. The concepts we use to analyse signs — structure, code, context, interpretation — apply directly to HTML, CSS, hyperlinks, and interface design. This site attempts to make that connection explicit.

Key Concepts at a Glance

Core technical terms used throughout this site. Definitions follow the MDN Web Docs Glossary.

Term Full name What it does
HTML HyperText Markup Language Defines the structure and content of a web page using tags
CSS Cascading Style Sheets Controls the visual presentation: colour, font, layout, spacing
HTTP HyperText Transfer Protocol The rules governing how browsers request and servers deliver pages
DNS Domain Name System Translates human-readable domain names into numeric IP addresses
TCP/IP Transmission Control Protocol / Internet Protocol Breaks data into packets and routes them across the network reliably
URL Uniform Resource Locator The unique address that identifies any resource on the Web
Hyperlink Hyperlink A clickable reference connecting one document to another on the Web
