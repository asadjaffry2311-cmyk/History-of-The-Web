1. Historical Development

The Web did not emerge from nowhere. It grew out of decades of research into networked computing, from the ARPANET experiments of the 1960s to Tim Berners-Lee's 1989 proposal at CERN. Each milestone introduced a concept — hypertext, URLs, HTTP, the browser — that made the next step possible.

2. Technical Structure

Behind every webpage is a conversation between a client and a server, governed by protocols. When you type a URL, DNS translates it into an IP address, TCP/IP breaks your request into packets, and HTTP defines how the server responds. Understanding these layers means understanding why the Web works the way it does.

3. Semiotic Relevance

The Web is not only a technical system — it is a space of signs. Links structure navigation as a form of argument. Page layouts guide attention and imply hierarchy. Interfaces encode assumptions about who a user is and what they need. Semiotics helps us read these choices critically, as designed meaning rather than neutral delivery.

Why This Topic Matters

The history of the Web is not simply a history of technology. It is a history of how human communication was reorganised. Before the Web, documents lived in libraries, archives, and filing cabinets — separate, static, and difficult to connect. After 1991, any document could link to any other document, anywhere on the planet, instantly. That single structural change — the hyperlink — rewired how knowledge is produced, stored, and shared.

At the same time, this transformation did not happen automatically. It required decisions: about protocols, about open standards, about who could publish and who could access. Tim Berners-Lee famously chose not to patent the Web, making it a public good. That choice shaped everything that followed. Studying the Web means asking not just how it works, but why it was built the way it was — and what values those choices encoded.

For students of semiotics, the Web is a particularly rich object of study. It is simultaneously an infrastructure and a text, a medium and a message. The concepts we use to analyse signs — structure, code, context, interpretation — apply directly to HTML, CSS, hyperlinks, and interface design. This site attempts to make that connection explicit.

Key Concepts at a Glance

These are the core technical terms used throughout this site. Each is explained in more depth on the How It Works and Timeline pages.

Term What it means Why it matters
HTML HyperText Markup Language — the structure of a web page Defines what content exists and how it is organised
CSS Cascading Style Sheets — the visual style of a page Controls how content looks: colour, font, layout
HTTP HyperText Transfer Protocol — the rules for exchanging data Governs how browsers request pages and servers respond
DNS Domain Name System — the Web's address book Translates human-readable URLs into numeric IP addresses
TCP/IP Transmission Control Protocol / Internet Protocol Breaks data into packets and routes them across the network
URL Uniform Resource Locator — a web address Identifies the precise location of a resource on the Web
